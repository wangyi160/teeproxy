# 信任与运行边界

teeproxy、agent、它们所在的用户主机及批准策略都在本机信任边界内。agent 通过回环 HTTP 直连 teeproxy，提示词、回答及可选本地 key 在这一段不使用 TLS；这要求同一台可信主机。teeproxy 不提供局域网监听，也不将本地 HTTP 方案用于远程客户端。

teeproxy 不生成本地 CA，不拦截供应商 TLS。它只连接配置中固定的 router HTTPS 地址。新建上游连接必须通过硬件证明、经审核的软件/启动策略及当前 TLS 通道绑定；成功之前不发送 router key 或业务数据。证书材料获取失败、未知策略、过期、调试或无签名证据均拒绝，没有未经验证的回退。

默认监听 127.0.0.1:8899；最多 128 个客户端连接、16 个并发请求，每个请求体及 gzip 解压后不超过 2 MiB。请求读取超时 30 秒，router 响应头超时 90 秒，流空闲默认 120 秒。请求名额保持到流完成、失败或取消。连接只在响应完整读取后复用，取消或错误使该连接关闭，已发送的请求不会由网关重放。

请求 Host 必须是监听 IP 或 localhost，端口必须匹配实际监听端口；URI 只接受 origin-form 的允许 API 路径。CONNECT、绝对目标 URL、浏览器 Origin/Sec-Fetch-Site 请求和管理 API 都会被拒绝。teeproxy 不按传入 Host 选择上游，不允许客户端改变上游目标。

可选 client_key_env 用于限制本机访问。teeproxy 清理 agent 认证、Cookie 和逐跳头，再设置固定 router key。额外自定义头仍可能转发，请勿在其中放其他服务密钥。程序不会记录请求体、回答或认证值，响应强制 Cache-Control: no-store。

Windows 桌面版的密钥由 DPAPI 以当前用户范围加密保存，运行时在本机内存中使用。界面记录操作与校验结果，不记录业务内容或密钥；显示密钥需要用户主动勾选。停止操作等待监听及已有客户端连接关闭后才允许重启，关闭窗口会结束后台运行。

router 及云平台仍须提供匹配批准策略的启动链。TEE 证明不代表供应商实际执行了某个模型，也不等于上游零日志。项目自带空批准策略；测试与历史签名样本不构成对任何实际部署的审批或生产安全审计。
