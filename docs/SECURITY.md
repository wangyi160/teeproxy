# 信任与运行边界

teeproxy、agent、它们所在的用户主机、本地 CA 私钥和发布策略都在用户信任边界内。teeproxy 终止 agent 的本地 TLS，因此能看到请求和响应；它不会记录请求体、响应体、供应商凭证或 router key。它不是隐藏本机恶意软件行为的隔离工具。

供应商 TLS 域名只用于 agent → teeproxy。teeproxy 不连接这些域名来转发推理，也不采用它们的公网证书来证明 router。router 身份仅由硬件证明、经审核的软件/启动策略以及当前通道绑定确立。CA 信任不能替代 TEE 校验。

监听必须为回环 IP；默认最多 128 个客户端连接、16 个并发请求，每个请求体不超过 2 MiB，gzip 解压后的上限相同。请求读取超时 30 秒、router 响应头超时 90 秒、流空闲默认 120 秒。客户端连接和 TLS 握手也有上限与超时。并发名额保持到流完成、失败或取消。

连接只在响应完整读取后才可复用；取消、错误或超时使该连接关闭。已发送的 POST 不会由代理重放。校验失败、证书材料获取失败、未知策略、过期/调试证据都会拒绝请求，没有降级到 sample 或未经验证服务器的选项。

请求 URI、Host、CONNECT 目标和配置路由必须一致；管理 API 不对代理客户端开放。代理清理逐跳头和供应商凭证，显式设置 router key。它不修改模型名、messages、instructions 或工具参数，也不会把失败转成虚假的模型回答。

router 及云平台仍必须提供匹配批准策略的启动链，限制调试、swap、磁盘和宿主权限。TEE 证明不代表供应商实际执行了某个模型，也不等于上游零日志。router 的运营和内存快照约束由 teerouter 项目说明。

项目自带空的批准策略。真实环境接入必须提供用户审核后的允许表；本地代理测试和公开硬件样本验证不构成对某个实际部署的审批或生产安全审计。
