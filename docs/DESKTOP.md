# Windows 原生桌面版

登录会话加密保存在程序旁的 `data/identity.dpapi`。用户名和密码另存于加密的 `data/login-passwords.dpapi`，登录页自动填入，账号页可查看；密码默认隐藏，支持显示 / 隐藏。启动时自动恢复并验证登录；连接暂时未绑定或停用不等于退出登录。正常使用会自动续期，连续 30 天未使用、主动退出或修改密码后需重新登录；临时断网不会清除会话。

`teeproxy.exe` 使用 Win32 系统窗口、文本框、按钮和文件选择器，支持键盘 Tab 导航及按显示器 DPI 缩放。双击即可打开配置界面，后台工作线程负责 TEE 验证与 API 转发。

Windows x86_64 发行包面向 Windows 10/11，解压后运行即可，无需管理员权限。使用左侧导航、右侧详情的两栏布局，同时包含 TDX 和 SNP 验证、模型和账号池列表以及系统托盘。

## 左侧导航与右侧详情

- **我的账户**：注册、登录、用户名、名称、连接状态、修改密码和退出登录。
- **余额与充值**：上方显示可用余额、充值网络和金额表单，下方左侧选择历史订单，右侧显示独立付款卡片。卡片展示收款地址二维码、网络、精确应付金额和倒计时，支持复制地址与金额。二维码仅包含地址，在本机生成；付款时仍需选择卡片中的网络并填写完整应付金额。订单过期或已付款后隐藏二维码并禁用复制付款信息。
- **消费明细**：今日和本月消费、调用与待核算数量、逐笔费用；选中记录后点击“消费凭据”查看并复制该笔签名 JSON。

账户功能直接通过 HTTPS 访问管理平台，使用原生控件，不打开浏览器。每次进入页面自动读取当前账户数据，充值订单每 15 秒刷新，其余每 5 分钟刷新。失败的订单创建保留同一操作编号供显式重试，不自动重复付款操作。

用户默认可使用所有启用商户的可用账号池，无需逐家申请。平台负责账户、余额、充值订单、费用与凭据的持久化。客户端不在本地保存财务数据副本。

Agent 使用的 **API key** 仅在本机生成、保存和校验，平台接口不接受该字段，也不将其发给 Router。平台另行签发内部连接凭据来识别扣费用户，由客户端自动领取，平台加密保管并同步给 Router。这不是用户需要复制或管理的第二套 API key。登录绑定接口只接收随机设备标识，不接收本地 IP、端口、路由配置或信任策略。

登录会话和连接身份使用当前 Windows 用户的 DPAPI 加密保存在 `data/identity.dpapi`。用户名和密码另存于加密的 `data/login-passwords.dpapi`，登录页自动填入，账号页可查看；密码默认隐藏，支持显示 / 隐藏。重新打开会恢复并验证会话；会话过期需要重新登录。退出登录立即停止该身份的代理、清空目录与账户内容、删除本机登录状态，同时保留本地 API key 和代理配置。旧版手工配置的 Router key 不会被误认为某个已登录用户的身份，首次升级需要登录。

- **概览**：顶部展示代理状态、当前账户和可用余额；中间是 Agent 的 API 地址、复制按钮与接入设置；底部并列展示路由模式、匹配策略或固定池、倍率上限，以及可用账号池和去重后的模型数量。各区域提供对应的日志、账户、充值、路由和目录入口。进入页面自动读取账户和目录，加载时显示动画，已有数据保留。
- **账号与模型**：一个页面包含三个联动列表。上方账号池每池一行，显示池名、商户、价格倍率、账号数量、模型提供商和状态；选中池后，下方左侧显示该池的账号、状态、模型目录和模型数，右侧显示该池可用的模型与接口。账号数量只统计可用账号；停用、不可用账号及没有可用账号的池不展示，其专属模型也不进入列表。搜索只作用于所选池的模型，切换池时清空搜索条件。模型 ID 使用 `chatgpt/模型名`、`claude/模型名`、`grok/模型名`；前缀代表模型提供商。同一模型在不同商户账号池中使用相同 ID，`/v1/models` 将其合并为一项。
- **Agent 接入**：本地监听 IP、端口，以及完整显示的 API key；可生成、手填、复制和保存。
- **连接与验证**：平台地址、自动绑定的 Router 地址、TDX/SNP 信任策略文件路径与浏览按钮。登录期间平台和 Router 地址锁定，退出后可修改。
- **运行记录**：查看验证、刷新、启动、停止和错误信息。
- **路由策略**：选择固定账号池或自动匹配，查看正在使用的策略与最近一次自动选中的池。
- **模型价格**：从管理平台读取当前可用账号池已开放模型的基准价；无可用账号、未开放或已移除的模型不展示，同一模型跨池去重。支持 ChatGPT、Claude、Grok 筛选和模型搜索；表格保留输入、输出、缓存读取及上下文/服务档位，下方显示缓存写入、数据来源、核对时间和价格版本。金额为美元/百万 Token，尚未乘账号池倍率；缺失价格显示“—”，不当作免费。

左下角显示代理状态，右上角按钮启动或停止代理；本地接入设置与 TEE 验证分属各自页面，列表刷新位于账号与模型页。

登录后，每次点击 **账号池与模型** 自动刷新；无需启动本地代理，页面可见时每 5 分钟更新。目录通过已登录的管理平台会话读取 `/portal/api/inventory`，与本地 `GET /v1/models` 共用按账户隔离的内存缓存，不连接 Router、不要求先完成 TEE 核验。管理平台快照随现有 5 分钟周期更新。账户尚未连接或其他操作尚未结束时，待就绪后自动读取；重复点击不会并发拉取。启动代理后也会刷新一次，仍可使用 **刷新列表** 主动更新。目录返回 401/403 时停止代理并关闭现有连接，清空目录与价格列表；普通网络故障不停止代理。后台 Agent 的目录查询同样适用，窗口最小化不影响停机。

首次加载时，空列表中央显示旋转指示；已有数据刷新时保留列表，刷新按钮显示动画。页面不显示说明性占位文字或重复的账号池摘要，错误仅以简短状态提示。

账户、充值、消费明细和价格页使用相同的加载动画：页面右上方显示转圈，空表格中央也显示转圈。刷新保留当前内容，完成、失败或取消后停止动画；登录、读取消费凭据和创建订单期间也显示页面加载状态。

模型价格页读取管理平台 `GET /portal/api/pricing`，每次进入时自动读取，也可点击 **刷新价格**，显示加载动画。该查询只读取管理平台缓存，不连接 Router、不要求本地代理运行。Router 每 5 小时从配置的 GitHub 数据源更新计费价格；管理平台复用差量检查点，价格未变化时每 5 小时更新缓存，价格版本发生变化时发布新版本，不为价格页另发 Router 查询。流水和余额仍按 5 分钟同步。价格页按平台最新可用模型目录筛选，短暂占满并发或测速失败不会删除仍可用的模型。Router 不再提供 `/v1/pricing`。

刷新失败会保留上次成功的列表并明确提示失败；修改 router、业务 key 或批准策略会清空旧列表，避免混用其他连接的结果。界面不创建、删除或登录上游账号，这些仍由 router 管理员处理。

浏览账号池、账号和模型不会修改路由。点击 **使用所选账号池** 保存池；选择模型后点击 **使用此池并复制模型**，还会复制完整模型 ID，可直接填到 Agent 配置。操作后仍留在当前页面，倍率上限保留；运行中保存后新请求立即使用该池，已有请求继续完成。代理通过 `X-Router-Routing` 发送已保存的路由规则，Router 根据提供商、模型、所选池和倍率上限确定请求目标，具体账号仍由 Router 调度。

三个列表同时可见，支持鼠标和键盘选择池。刷新时按完整池 ID 保留选择，即使列表排序改变也不会串池；所选池被移除后同时清空账号和模型明细，等待重新选择。停用或不可用的账号不显示，没有可用账号的池随刷新移除；恢复可用后重新出现。测速失败不单独视为账号不可用。

## 配置上游

1. 在 **我的账户** 注册或登录，程序自动领取当前设备的连接身份；等待 Router 完成下发后显示“已绑定”。首次绑定不阻塞登录页面，后台会查询下发状态。
2. 在 **连接与验证** 使用 **浏览文件** 指定独立审核过的 TDX 或 SNP 发布策略，点击 **保存**。软件不会自动批准服务器提供的发布信息。
3. 在 **Agent 接入** 设置 IP、端口与 API key，点击 **保存**。支持 `127.0.0.1`、本机 IP、`0.0.0.0` 和 `::`；所有监听地址都要求 16–256 个可见 ASCII 字符的 API key。
4. 在 **路由策略** 选择固定池或自动匹配，设置倍率上限。
5. **启动代理**，将概览中的本地地址和本地 API key 填入 Agent。保存失败会保留输入并显示具体原因。

使用 `0.0.0.0` 时，概览显示本机可用的 `http://127.0.0.1:端口/v1`；其他设备填写这台电脑的实际局域网 IP，例如 `http://192.168.1.6:8899/v1`。`0.0.0.0` 是监听地址，不是远程客户端的目标地址。IPv6 接入地址使用方括号，例如 `http://[::1]:8899/v1`。局域网入口仍使用 HTTP，应在可信网络中使用；网络设备能否连接还取决于本机防火墙。

`https://router.example.com:8443` 仅为地址格式示例。项目自带的空策略不会批准任何实例，第一次接入仍需要用户准备可信策略。

## 固定账号池与自动匹配

先刷新可信目录，再打开 **路由策略**。选择 **指定账号池** 时，下拉列表显示池名、商户和倍率。运行中可修改模式、账号池、倍率上限及优先策略，点击 **保存路由设置** 后，新请求立即采用整组新规则。未保存的编辑不会改变运行规则，界面会标出“未保存”；保存失败时继续使用原规则。旧桌面配置中已有的池会保留，浏览其他池不会更换路由。

每个请求在接收时固定一份路由规则，直到该请求结束；保存新规则不会中断已有流式响应，也不会用新倍率上限去重新检查旧请求的响应。尚未启动代理时，保存的规则用于下次启动。

两种模式都必须遵守 **倍率上限**，默认 1×，最多 6 位小数。例如设置 0.5 时，当前倍率等于 0.5× 可以使用，高于 0.5× 则由 Router 拒绝调用上游。切换账号池会保留上限，不会自动提高。固定池超限返回 HTTP 403 `routing_multiplier_exceeded`，也不会改用其他池。

选择 **自动匹配账号池** 时，可设置以下条件：

| 设置 | 行为 |
| --- | --- |
| 倍率上限 | 相对官方基准的最高倍率，最多 6 位小数；例如 0.5 表示最多 0.5× |
| 费率优先 | 在满足授权、模型、接口、可用状态和倍率限制的池中比较包含缓存读写的预计总费用 |
| 低延迟优先 | Router 每 5 分钟通过各账号配置的代理探测官方 API 链路，优先复用原会话账号，再比较连接延迟；不产生模型 Token 用量 |

“账号池与模型”页面的池列表显示最低链路延迟，账号列表显示各自链路延迟，单位为 ms，并显示本地时区的测速时间。未测速、失败、过期、不可用分别标注；延迟是 Router 通过代理到官方入口的探测结果，不是模型生成速度。池级结果是可用账号中最低的有效延迟，会话粘性仍可能选择其他账号。登录后此页可见时每 5 分钟刷新目录，也可点击“刷新列表”；旧测量到期后自动显示“已过期”。

低延迟是代理隧道、TLS 和 HTTP 响应头的综合耗时，不表示模型生成速度。探测在 Router 后台进行，客户端不测速。没有有效样本时按可用性、粘性及预计费用兜底；旧配置中的 `speed` 自动对应低延迟优先。

模型始终按 Agent 请求中的精确 ID 和接口匹配，不再单独设置大类或小类，也不会改写请求。自动模式在当前 key 有权限的兼容池中选择。没有合适的账号池时返回 `routing_no_matching_pool`，不会降级到超出倍率上限或其他模型的池。0.10 版配置中的旧模型选择字段会被忽略，下次保存时移除；倍率上限会保留。

teeproxy 通过 `X-Router-Routing` 将模式、固定池（如有）、倍率上限和优先策略随每次请求发送给 Router。Router 在 TEE 内按同一份配置及报价快照完成匹配和准入，账务归档该次实际报价；不依赖客户端目录快照或价格版本检查。客户端不在生成前读取 `/v1/models` 或 `/v1/pools` 来选路，目录只用于界面浏览。

每条已验证的 TLS 连接首次转发业务请求前会协商路由规则 v1；旧 Router 不支持时返回 `router_routing_protocol_required`，不发送业务请求。teeproxy 覆盖调用方的池、账号、报价版本和规则头，避免覆盖已配置的策略。Router 在调用上游前执行路由和倍率约束。响应中的账号池和倍率仅用于展示；teeproxy 不再次比较固定池、倍率上限或响应协议版本，也不会因字段缺失或格式不符阻断回复。账号池和倍率只在 teeproxy 界面展示；`X-Router-*` 和 `X-Teeproxy-*` 内部响应头不发给 Agent。请求不会自动重放，Router 的状态与正文直接返回 Agent。详见 [路由协议](https://github.com/wangyi160/teerouter/blob/main/docs/API.md#请求路由规则-v1)。

Router 测速按账号池、模型和接口分别记录，使用移动平均；10 分钟后样本过期。未测过或已过期的池从后续真实请求中轮流积累样本，不额外发送探测请求。有流式生成内容后才计首字时间，心跳和角色元数据不计；上游提供输出 token 数、且首末内容之间至少间隔 250 ms 时才估算 token/s，避免将集中吐出的短突发误当作极高生成速度。非流式响应不能得到真实首字时间，不伪造速度；失败、截断和取消的响应不作为成功测速。样本仅留在 Router 内存中，所有客户端使用其统一观测，不保存请求或回复正文。

两种模式均将路由规则随公共 `/v1/` 业务请求交给 Router，无需 teeproxy 理解供应商协议。命令行固定模式未配置 `pool` 时，业务请求返回 `routing_pool_required`，本地模型目录仍可读取。当前可用池少于两个时无需比较速度；这不代表已经测得其他池的性能。

## 运行行为

- 界面的“运行中”表示本地 API 已监听；每条上游业务连接仍必须独立完成 TEE 和 TLS 绑定校验。
- “验证连接”不启动监听，也不发送 router key。校验结果只表示本次检查；之后的业务连接重新校验。
- 路由规则支持运行中保存并即时生效。上游地址、API key、TEE 批准策略和监听 IP/端口属于连接设置，运行时仍锁定，修改这些设置需先停止代理，保存后再启动。
- 右上角按钮在运行时显示“停止代理”，单独验证或刷新时显示“取消操作”；点击后取消后台任务并关闭监听及所有客户端流，完成后恢复“启动代理”。
- **最小化或点击窗口关闭按钮会隐藏到 Windows 右下角系统托盘，网关继续转发。** 点击托盘图标可恢复窗口；右键菜单可以打开窗口、启动/停止网关或退出。选择 **退出 teeproxy** 才会结束程序并释放端口。
- 若系统托盘注册失败，窗口保留在任务栏，关闭按钮会退出，避免留下无法操作的隐藏程序。Explorer 重启后会重新注册托盘图标。
- 软件不自动启动监听，不设置开机启动、不改写 agent 配置，也不安装证书。需要运行时打开窗口并点击启动。
- Agent 接入中的 **API key** 用于 Agent 接入。保存后再次打开软件会自动加载并明文显示，方便核对与复制；Agent 填写同一个值。必填，空值无法保存或启动代理。router key 始终由 teeproxy 持有。

Codex 使用 `http://127.0.0.1:端口/v1`；Claude Code 的 `ANTHROPIC_BASE_URL` 使用 `http://127.0.0.1:端口`。详见 [客户端接入](CLIENTS.md)。

## 保存位置

Windows 版是免安装便携程序，默认只在 `teeproxy.exe` 同目录的 `data` 文件夹保存数据，与启动时的工作目录无关：

```text
teeproxy.exe
data/
  desktop.json
  identity.dpapi
  device-id
  account-platform.json
  policies/
    phala-tdx.json
```

点击“保存设置”后，选自其他目录的 TDX/SNP 策略会原样复制到 `data/policies/`，界面与配置使用相对路径。`data` 内已有的策略保存为相对于 `data` 的路径。同名但内容不同的策略使用带摘要的文件名，避免覆盖已保存的策略。移动软件时带上整个文件夹；升级时替换程序，保留 `data`。程序目录不可写会明确报错，不会改存到 AppData。

首次升级时，若没有 `data/desktop.json`，会从旧版 `%LOCALAPPDATA%\teeproxy\desktop.json` 迁入配置、API key 及策略副本。已有的便携配置优先；旧文件保留作为备份，之后不再使用或更新。迁移失败会报错，不会用空配置覆盖旧数据。

上游地址、端口、路由和策略路径以普通配置存储。本地 API key 由 DPAPI 加密保存在 desktop.json；登录会话和内部连接凭据保存在独立的 identity.dpapi。文件不含明文凭据。同一 Windows 用户下移动目录无需重新填写 API key；换用户或换电脑通常不能解密，需要重新配置凭证。损坏或无法解密的配置会显示错误，不会静默覆盖原文件。

修改表单后需要点击“保存设置”，未保存的值仍可用于本次验证和运行。复制策略文件不会修改批准的发布项，连接前仍须通过完整 TEE 校验。

可通过 `teeproxy.exe gui --settings C:\path\desktop.json` 使用单独的桌面配置。桌面设置与命令行的 `teeproxy.toml` 分开保存；命令行仍通过环境变量读取业务 key。

TDX 为默认构建功能，SNP 需要 `--features snp-verifier` 或 `--all-features`。界面会提示当前构建是否包含 SNP 验证。

Windows 发布前可运行 `tests/windows_desktop.ps1`，验证原生账户页面、本地设置与身份分离、API key 保存恢复、未登录禁止启动、验证失败与托盘生命周期。加上 `-Portable` 会通过默认启动入口检查便携目录、外部策略复制、整个文件夹移动后的恢复及不写入 AppData。脚本仅使用本地隔离目录和测试 API key，不会接入真实 router。
