# Windows 原生桌面版

`teeproxy.exe` 使用 Win32 系统窗口、文本框、按钮和文件选择器，支持键盘 Tab 导航及按显示器 DPI 缩放。双击即可打开配置界面，后台工作线程负责 TEE 验证与 API 转发。

Windows x86_64 发行包面向 Windows 10/11，解压后运行即可，无需管理员权限。使用左侧导航、右侧详情的两栏布局，同时包含 TDX 和 SNP 验证、模型和账号池列表以及系统托盘。

## 左侧导航与右侧详情

- **概览**：复制本地 API 接入地址，查看当前上游地址、可访问模型数和账号池数。尚未刷新时显示“未读取”。
- **账号与模型**：一个页面包含三个联动列表。上方账号池每池一行，显示池名、商户、价格倍率、账号数量、模型提供商和状态；选中池后，下方左侧显示该池的账号、状态、模型目录和模型数，右侧显示该池可用的模型与接口。账号数量包含停用账号，空池显示 0。搜索只作用于所选池的模型，切换池时清空搜索条件。模型 ID 使用 `chatgpt/模型名`、`claude/模型名`、`grok/模型名`，测试池使用 `workbuddy/模型名`；前缀代表模型提供商。同一模型在不同商户账号池中使用相同 ID，`/v1/models` 将其合并为一项。
- **连接设置**：配置 router 地址、业务密钥、批准策略、本地端口和可选本地密钥。
- **运行记录**：查看验证、刷新、启动、停止和错误信息。
- **路由策略**：选择固定账号池或自动匹配，查看正在使用的策略与最近一次自动选中的池。
- **官方价格**：独立读取 Router 的完整官方价格簿，即使没有上游账号或账号池，也可查看已发布模型的价格。支持 ChatGPT、Claude、Grok 筛选和模型搜索；表格列出输入、输出、缓存读取及上下文/服务档位，下方显示缓存写入、官方来源、核对时间和价格版本。金额为美元/百万 Token，尚未乘账号池倍率；缺失价格显示“—”，不当作免费。

左下角显示代理状态，右上角按钮启动或停止代理；保存与验证位于连接设置页，列表刷新位于账号与模型页。

点击 **刷新列表** 时，先完成 TEE 及 TLS 绑定验证，再在同一条已验证连接上使用业务 key 读取 `/v1/models` 和 `/v1/pools`。不需要管理员密钥，不读取上游凭据。启动代理后也会刷新一次；账号状态是刷新时的快照，需要最新状态时再次点击刷新。

官方价格页单独通过相同的 TEE 验证读取 `GET /v1/pricing`，首次打开时自动读取，也可点击 **刷新价格**。本地代理运行中，该只读接口同样可通过 `http://127.0.0.1:端口/v1/pricing` 使用。它不依赖模型目录或账号池，不开放管理员价格写入接口。显示的是 Router 已发布的价格簿，不是客户端实时抓取官网；有报价不意味着当前用户可调用该模型。旧 Router 没有此接口时明确提示升级，不用账号池报价冒充完整官方价格。

刷新失败会保留上次成功的列表并明确提示失败；修改 router、业务 key 或批准策略会清空旧列表，避免混用其他连接的结果。界面不创建、删除或登录上游账号，这些仍由 router 管理员处理。

浏览账号池、账号和模型不会修改路由。点击 **使用所选账号池** 保存池；选择模型后点击 **使用此池并复制模型**，还会复制完整模型 ID，可直接填到 Agent 配置。操作后仍留在当前页面，倍率上限保留；运行中保存后新请求立即使用该池，已有请求继续完成。代理通过 `X-Router-Routing` 发送已保存的路由规则，Router 根据提供商、模型、所选池和倍率上限确定请求目标，具体账号仍由 Router 调度。

三个列表同时可见，支持鼠标和键盘选择池。刷新时按完整池 ID 保留选择，即使列表排序改变也不会串池；所选池被移除后同时清空账号和模型明细，等待重新选择。停用、目录获取失败或没有匹配模型的池会显示相应提示。

## 配置上游

1. 打开 **连接设置**，在 **Router 地址** 填写上游 HTTPS 根地址，例如 `https://router.example.com:8443`。不要添加 `/v1`，也不要把密钥放进 URL。
2. 在 **业务密钥** 填写 router 的普通业务 key。
3. 用 **选择文件** 指定本机审核后的 TDX 或 SNP 发布策略。对应运行环境填写其中一种即可。软件不会根据服务器传来的证据自动批准发布。
4. 设置本地端口，默认 `8899`，本地 key 可选。在 **路由策略** 选择固定账号池或自动匹配。
5. 点击 **保存设置**。点击 **验证连接** 可单独检查真实连接；点击右上角 **启动代理** 后，在概览页复制地址并填到 agent 的 base URL。

`https://router.example.com:8443` 仅为地址格式示例。项目自带的空策略不会批准任何实例，第一次接入仍需要用户准备可信策略。

## 固定账号池与自动匹配

先刷新可信目录，再打开 **路由策略**。选择 **指定账号池** 时，下拉列表显示池名、商户和倍率。运行中可修改模式、账号池、倍率上限及优先策略，点击 **保存路由设置** 后，新请求立即采用整组新规则。未保存的编辑不会改变运行规则，界面会标出“未保存”；保存失败时继续使用原规则。旧桌面配置中已有的池会保留，浏览其他池不会更换路由。

每个请求在接收时固定一份路由规则，直到该请求结束；保存新规则不会中断已有流式响应，也不会用新倍率上限去重新检查旧请求的响应。尚未启动代理时，保存的规则用于下次启动。

两种模式都必须遵守 **倍率上限**，默认 1×，最多 6 位小数。例如设置 0.5 时，当前倍率等于 0.5× 可以使用，高于 0.5× 则由 Router 拒绝调用上游。切换账号池会保留上限，不会自动提高。固定池超限返回 HTTP 403 `routing_multiplier_exceeded`，也不会改用其他池。

选择 **自动匹配账号池** 时，可设置以下条件：

| 设置 | 行为 |
| --- | --- |
| 倍率上限 | 相对官方基准的最高倍率，最多 6 位小数；例如 0.5 表示最多 0.5× |
| 费率优先 | 在满足授权、模型、接口、可用状态和倍率限制的池中选择最低倍率 |
| 速率优先 | 按 Router 观测的真实流式请求测速，首字时间优先，同一 100 ms 区间内再比较 token/s |

模型始终按 Agent 请求中的精确 ID 和接口匹配，不再单独设置大类或小类，也不会改写请求。自动模式在当前 key 有权限的兼容池中选择，包括可用的 Workbuddy 测试池。没有合适的账号池时返回 `routing_no_matching_pool`，不会降级到超出倍率上限或其他模型的池。0.10 版配置中的旧模型选择字段会被忽略，下次保存时移除；倍率上限会保留。

teeproxy 通过 `X-Router-Routing` 将模式、固定池（如有）、倍率上限和优先策略随每次请求发送给 Router。Router 在 TEE 内按同一份配置及报价快照完成匹配和准入，账务归档该次实际报价；不依赖客户端目录快照或价格版本检查。客户端不在生成前读取 `/v1/models` 或 `/v1/pools` 来选路，目录只用于界面浏览。

每条已验证的 TLS 连接首次生成前会协商路由规则 v1；旧 Router 不支持时返回 `router_routing_protocol_required`，不发送生成请求。teeproxy 覆盖调用方的池、账号、报价版本和规则头，避免覆盖已配置的策略。Router 返回实际池、倍率与已应用的协议版本，teeproxy 检查响应并显示结果，同时保留 `X-Teeproxy-Pool` 和 `X-Teeproxy-Multiplier` 兼容头。生成请求不会自动重放，Router 的拒绝状态与正文直接返回 Agent。详见 [路由协议](https://github.com/wangyi160/teerouter/blob/main/docs/API.md#请求路由规则-v1)。

Router 测速按账号池、模型和接口分别记录，使用移动平均；10 分钟后样本过期。未测过或已过期的池从后续真实请求中轮流积累样本，不额外发送探测请求。有流式生成内容后才计首字时间，心跳和角色元数据不计；上游提供输出 token 数、且首末内容之间至少间隔 250 ms 时才估算 token/s，避免将集中吐出的短突发误当作极高生成速度。非流式响应不能得到真实首字时间，不伪造速度；失败、截断和取消的响应不作为成功测速。样本仅留在 Router 内存中，所有客户端使用其统一观测，不保存请求或回复正文。

两种模式支持 Chat Completions、Responses 和 Messages；无法校验报价的其他生成协议拒绝转发。命令行固定模式未配置 `pool` 时，生成请求返回 `routing_pool_required`，目录查询仍可使用。当前可用池少于两个时无需比较速度；这不代表已经测得其他池的性能。

## 运行行为

- 界面的“运行中”表示本地 API 已监听；每条上游业务连接仍必须独立完成 TEE 和 TLS 绑定校验。
- “验证连接”不启动监听，也不发送 router key。校验结果只表示本次检查；之后的业务连接重新校验。
- 路由规则支持运行中保存并即时生效。上游地址、密钥、TEE 批准策略和监听端口属于连接设置，运行时仍锁定，修改这些设置需先停止代理。
- 右上角按钮在运行时显示“停止代理”，单独验证或刷新时显示“取消操作”；点击后取消后台任务并关闭监听及所有客户端流，完成后恢复“启动代理”。
- **最小化或点击窗口关闭按钮会隐藏到 Windows 右下角系统托盘，网关继续转发。** 点击托盘图标可恢复窗口；右键菜单可以打开窗口、启动/停止网关或退出。选择 **退出 teeproxy** 才会结束程序并释放端口。
- 若系统托盘注册失败，窗口保留在任务栏，关闭按钮会退出，避免留下无法操作的隐藏程序。Explorer 重启后会重新注册托盘图标。
- 软件不自动启动监听，不设置开机启动、不改写 agent 配置，也不安装证书。需要运行时打开窗口并点击启动。
- 默认未设置本地 key；配置后，将该 key 同时填到 agent 的 API key。router key 始终由 teeproxy 持有。

Codex 使用 `http://127.0.0.1:端口/v1`；Claude Code 的 `ANTHROPIC_BASE_URL` 使用 `http://127.0.0.1:端口`。详见 [客户端接入](CLIENTS.md)。

## 保存位置

桌面配置默认位于 `%LOCALAPPDATA%\teeproxy\desktop.json`。上游地址、端口和策略路径以普通配置存储，router key 与本地 key 使用当前 Windows 用户的 DPAPI 加密后保存。配置文件不会包含明文 key；它仍应保存在自己的用户目录中。其他用户或设备通常无法解密，需要重新填写密钥。

相对策略路径以桌面配置文件所在目录为基准；文件选择器保存完整路径。修改表单后需要点击“保存设置”，未保存的值仍可用于本次验证和运行。损坏或无法解密的配置会显示错误，软件不会静默覆盖原文件。

可通过 `teeproxy.exe gui --settings C:\path\desktop.json` 使用单独的桌面配置。桌面设置与命令行的 `teeproxy.toml` 分开保存；命令行仍通过环境变量读取业务 key。

TDX 为默认构建功能，SNP 需要 `--features snp-verifier` 或 `--all-features`。界面会提示当前构建是否包含 SNP 验证。

Windows 发布前可运行 `tests/windows_desktop.ps1`，验证侧栏导航、保存和恢复、密钥遮挡、验证/刷新失败、托盘恢复、最小化/关闭后继续服务及停止/退出后的端口释放。脚本仅使用本地隔离目录和测试密钥，不会接入真实 router。
